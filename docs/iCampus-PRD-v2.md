# iCampus 产品需求文档 (PRD)

> **产品名称**：iCampus（原 CampusPal）
> **版本**：v2.0 重构规划
> **产品形态**：微信小程序 + FastAPI 后端
> **目标用户**：在校大学生
> **文档日期**：2026-07-26

---

## 1. 产品概述

iCampus 是一款面向中国大学生的 AI 校园助手，覆盖**日常管理**、**成长决策**、**长期规划**三大核心场景。产品通过"首页 → 今日模式 → 成长模式"三层递进，从每一天的课程与待办，到人生关键节点的路径对比与深度规划，提供全周期的 AI 陪伴。

---

## 2. 页面架构总览

```
首页 (Home)
 ├── 吉祥物 + 打招呼语（根据时间段变化）
 ├── 天气组件
 ├── 今日概览卡片群
 │    ├── 今日课程
 │    ├── 待办事项
 │    ├── 最近考试（两周内有则显示最近一场，否则显示"最近没有考试"）
 │    └── 校园通知（暂不开发）
 ├── AI 建议（综合天气 + 当天事宜）
 └── 点击"今日概览"区域 → 进入今日模式

今日模式 (Today)
 ├── 日历组件（默认展示一周，可展开为整月）
 │    └── 点击任意日期查看当日事件
 ├── 时间轴（展示具体时间段事件，如课程、考试，含时间+教室）
 ├── PDF 导入（课程表 / 考试表自动同步）
 ├── 手动添加事件
 ├── AI 建议（天气 + 当天事宜 + 日程间隙建议）
 ├── [待定] AI 聊天入口
 └── 待办事项列表
      └── 每个待办左侧有小圆，点击打勾（完成），再点删除

成长模式 (Growth)
 ├── 沙盒模式（对比）
 │    ├── 追问 → 弹出路径选择 → 各路径针对性追问
 │    ├── 提示开始比对 → 输出对比结论报告
 │    └── 弹出四个规划 Agent 入口卡片（标注匹配度，可选进入）
 │
 └── 规划模式（深度规划）
      ├── 进入后打招呼语（如就业："准备好开始了吗？"）
      ├── 用户回答"准备好了" → 先分析并补充信息，按需追问0~5个高价值问题
      ├── Agent 提示"可以开始规划"
      ├── 用户说"开始规划" → 输出规划报告
      └── 记忆延续：使用沙盒阶段采集的用户画像，不重复追问

长期记忆系统
 ├── AI 自动提取 + 存入
 ├── 系统自动更新 / 新增
 ├── 用户可查看、编辑、删除
 └── 跨模式共享（沙盒 → 规划 → 今日）
```

## 3. 功能详述

---

### 3.1 首页 (Home)

首页是用户打开小程序的第一屏，追求**轻量 + 关怀感**。

#### 3.1.1 顶部区域

| 元素 | 说明 |
|---|---|
| 吉祥物 | 应用 IP 形象，固定展示在顶部 |
| 打招呼语 | 根据当前时间段动态变化，如"早上好！""下午好！""晚上好！" |
| 天气组件 | 展示所在城市当前天气（温度、天气状况图标），支持自动定位 |

#### 3.1.2 今日概览卡片群

以卡片矩阵形式展示四项关键指标：

| 卡片 | 逻辑 |
|---|---|
| 今日课程 | 当天课程节数，点击进入今日模式查看详情 |
| 待办事项 | 当天未完成的待办数量 |
| 最近考试 | 两周内有考试则显示最近一场（科目+日期+倒计时），超过两周显示"最近没有考试" |
| 校园通知 | 占位卡片，标注"暂不开发" |

点击整个"今日概览"区域均可跳转至今日模式。

#### 3.1.3 AI 建议

与今日模式共用同一 AI 建议逻辑（见 3.2.5），在首页以精简版展示。

#### 3.1.4 待办事项快捷列表

首页下方展示待办事项列表，包含：

- 小组课作业
- 日常作业
- 要交的报告
- 其他自定义事项

每个待办事项左侧有一个**小圆图标**：
- 点击小圆 → 打勾标记为"已完成"
- 再次点击已勾选小圆 → 删除该事项（即完成确认）

#### 3.1.5 待办来源

- 用户手动添加
- 后期：教师端发布自动同步

---

### 3.2 今日模式 (Today)

从首页点击"今日概览"区域进入，是高频使用的日程管理页面。

#### 3.2.1 日历组件

| 特性 | 说明 |
|---|---|
| 默认视图 | 展示当前一周（7 天），高亮"今天" |
| 展开能力 | 可展开为整月视图 |
| 日期点击 | 点击任意日期，下方时间轴切换至该日事件 |
| 事件标记 | 有事件的日期以圆点/色块标记 |

#### 3.2.2 时间轴

按时间顺序纵向排列当日所有事件：

| 字段 | 说明 |
|---|---|
| 事件类型 | 课程 / 考试 / 自定义事件 |
| 时间段 | 如 08:00 - 09:40 |
| 事件名称 | 如"高等数学" |
| 地点 | 如"教三楼 201" |
| 状态标签 | 进行中 / 未开始 / 已结束 |

#### 3.2.3 PDF 导入

| 功能 | 说明 |
|---|---|
| 课程表导入 | 上传 PDF 格式课程表，AI 自动解析并同步至日历 |
| 考试表导入 | 上传 PDF 格式考试安排，自动解析并标记为考试事件 |
| 解析反馈 | 解析完成后展示识别结果，用户可校对修正 |

#### 3.2.4 手动添加事件

用户可手动创建事件，必填字段：

- 事件名称
- 日期
- 时间段（开始 / 结束）
- 地点（可选）
- 事件类型（课程 / 考试 / 其他）

#### 3.2.5 AI 建议

综合以下因素生成每日建议：

- 当日天气（温度、降雨概率）
- 当日课程与考试安排
- 日程空闲时段
- 待办事项优先级

示例：「今天有雨，记得带伞。上午高数课后有两小时空档，建议复习英语词汇。」

#### 3.2.6 待定项目

| 项目 | 状态 |
|---|---|
| AI 聊天 | 待定，考虑在今日模式中嵌入 AI 对话入口 |
| 教师端同步 | 后期开发，教师发布后自动同步至学生今日模式 |

### 3.3 成长模式 (Growth)

成长模式分为两个子模式：**沙盒模式**（对比探索）与**规划模式**（深度规划）。

#### 3.3.1 沙盒模式（对比）

沙盒模式的定位是**路径对比**，帮助用户看清不同选择的差异，而非代替后续规划 Agent 的工作。

**流程：**

```
进入沙盒 → 打招呼语
   ↓
追问阶段（通用）：多轮对话了解用户背景、性格、能力、兴趣
   ↓
路径选择：弹出选项卡，用户勾选要对比的路径
   ├── 就业 (career)
   ├── 考研 (graduate)
   ├── 考公 (civil)
   └── 转专业 (major)
   ↓
针对性追问：对每条选中路径追问 1~2 个定制问题
   ↓
用户提示"开始比对"
   ↓
AI 输出对比结论报告
   ↓
弹出四个规划 Agent 入口卡片
   ├── 每张卡片标注该路径的匹配度（百分比或星级）
   └── 用户可选择任一 Agent 进入规划模式
```

**关键约束：**

| 约束 | 说明 |
|---|---|
| 报告聚焦对比 | 沙盒报告只做路径差异分析，不做具体规划方案 |
| 记忆延续 | 沙盒阶段采集的用户画像自动存入长期记忆，规划阶段直接调用，避免重复提问 |
| 报告不替代规划 | 对比报告给出的结论为方向性建议，深度方案由后续规划 Agent 完成 |

**不同模式的打招呼语各不同**（详见 3.3.3）。

#### 3.3.2 规划模式（深度规划）

用户从沙盒选择一条路径后进入，或直接从成长模式入口选择规划 Agent 进入。

**流程：**

```
进入规划 Agent → 打招呼语
   ↓ （不同 Agent 打招呼语不同，如就业 Agent："准备好开始规划你的职业道路了吗？"）
用户回答"准备好了"
   ↓
建议式对话阶段：Agent 先分析并补充领域信息，再按需提出0~5个针对性问题
   ↓
Agent："信息收集完毕，可以开始规划了"
用户说"开始规划"
   ↓
Agent 输出规划报告（SSE 流式）
```

**四个规划 Agent：**

| Agent | 核心能力 |
|---|---|
| 就业规划 | 岗位定位、能力缺口、技能路线、简历建议、90 天求职计划 |
| 考研规划 | 院校匹配、专业方向、复习时间线、导师建议 |
| 考公规划 | 岗位匹配、行测/申论策略、面试准备、时间线 |
| 转专业规划 | 目标专业分析、先修课程、转专业流程、备选方案 |

**关键约束：**

| 约束 | 说明 |
|---|---|
| 记忆调用 | 优先读取长期记忆中的已有画像，不重复提问 |
| 追问策略 | 先分析和补充信息，再按决策价值追问；每轮最多1个，个性化建议前最多5个，允许0追问；用户不知道或跳过时不重复追问 |
| 用户驱动 | 追问结束后等待用户说"开始规划"才生成报告 |

**个性化建议充分度：** 每个方向均设置5个信息维度，至少覆盖4个且满足必备项后，才允许输出个性化建议。

| 方向 | 必备项 | 其余维度（至少再覆盖1项） |
|---|---|---|
| 考研 | 专业与年级、目标方向/岗位、学业与备考基础 | 读研动机、时间与现实约束 |
| 就业 | 专业与求职阶段、目标岗位、技能/项目/实习证据 | 城市行业偏好、收入强度与稳定性约束 |
| 考公 | 专业与报考阶段、考公动机、考试地区与岗位范围 | 行测申论基础、备考投入与备选方案 |
| 转专业 | 当前专业年级与学校条件、转专业原因、目标专业 | 目标专业基础、政策时间与家庭约束 |

未达到标准且仍可提问时，只输出通用信息和判断框架。用户回答“不知道/不清楚/不方便回答”后，将该项标为暂不可用并转向其他维度；达到5问上限或没有可问变量时，改为条件式建议，明确假设与不确定性。

#### 3.3.3 打招呼语定义

不同入口使用不同打招呼语，增强场景感：

| 入口 | 打招呼语示例 |
|---|---|
| 沙盒模式入口 | "让我们一起来探索你的可能性，准备好了吗？" |
| 就业规划 Agent | "准备好开始规划你的职业道路了吗？" |
| 考研规划 Agent | "准备好一起制定你的考研计划了吗？" |
| 考公规划 Agent | "准备好规划你的考公之路了吗？" |
| 转专业规划 Agent | "准备好探索新的专业方向了吗？" |

### 3.4 长期记忆系统

#### 3.4.1 记忆类型

| 类型 | 示例 |
|---|---|
| 用户画像 | 性格特征、MBTI、兴趣爱好 |
| 学业背景 | 学校、专业、年级、GPA |
| 能力评估 | 编程能力、英语水平、沟通能力 |
| 成长目标 | 长期职业方向、短期学业目标 |
| 偏好倾向 | 城市偏好、行业偏好、工作节奏偏好 |

#### 3.4.2 记忆生命周期

| 操作 | 触发方 | 说明 |
|---|---|---|
| 自动提取 | 系统 | AI 在对话中识别关键信息后自动存入 |
| 自动更新 | 系统 | 当对话中出现与已有记忆矛盾的新信息时，自动更新 |
| 查看 | 用户 | 记忆面板查看所有已存储画像 |
| 编辑 | 用户 | 用户可修改任意记忆条目 |
| 删除 | 用户 | 用户可删除任意记忆条目 |

#### 3.4.3 跨模式共享

```
沙盒阶段提取的画像
   ↓ 自动存入长期记忆
规划阶段调用
   ↓ 避免重复提问
今日模式辅助（如 AI 建议参考用户偏好）
```

### 3.5 待办事项体系

| 来源 | 说明 |
|---|---|
| 手动添加 | 用户在首页或今日模式中创建 |
| 教师端发布（后期） | 教师通过教师端发布作业/报告，自动同步 |

交互逻辑：

```
待办列表项 [○] 每日英语听力练习
           ↓ 点击小圆
         [✓] 每日英语听力练习  （标记完成）
           ↓ 再次点击
         [已删除]             （从列表移除）
```

## 4. 后期规划

### 4.1 教师端

- Web 端后台管理
- 课程发布、考试发布、作业发布
- 发布后自动同步至学生端今日模式

### 4.2 成长模式 ↔ 今日模式联动

| 场景 | 说明 |
|---|---|
| 规划生成每日计划 | 如就业 Agent 输出 30 天 / 90 天每日行动计划 |
| 用户确认同步 | 用户确认后，计划自动写入今日模式的日历和待办 |
| 进度追踪 | 今日模式完成情况反馈给成长模式，评估计划执行率 |

### 4.3 校园通知

- 首页"校园通知"卡片后续对接学校公告系统

## 5. 与旧版 CampusPal 的核心差异

| 维度 | CampusPal (v1.0) | iCampus (v2.0) |
|---|---|---|
| 首页 | 今日概览卡片 + AI 建议 | 新增吉祥物、时间段打招呼语、待办快捷操作 |
| 今日模式 | 基础时间轴 | 新增日历组件（周/月）、PDF 导入、手动事件、待办交互 |
| 成长模式 | 沙盘四阶段 → Agent | 重构为沙盒对比 + 规划 Agent 两段式，明确职责分离 |
| 记忆系统 | 自动提取 + CRUD | 强化跨模式共享，自动更新，规划阶段无缝衔接 |
| 待办 | 简单展示 | 点击打勾/删除交互，预留教师端同步 |
| 打招呼语 | 单一 | 各模式/Agent 独立打招呼语 |
| 后期联动 | 无 | 成长规划 ↔ 今日模式自动同步 |

## 6. 技术约束

| 项 | 说明 |
|---|---|
| 前端 | 微信小程序原生（WXML / WXSS / JS） |
| 后端 | FastAPI (Python 3.11+) |
| AI | DeepSeek API |
| 数据库 | SQLite (SQLAlchemy ORM) |
| 工作流 | LangGraph + AsyncSqliteSaver |
