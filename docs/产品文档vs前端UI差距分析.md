## 四、概念描述偏差

### 4.1 Agent 命名

| 产品文档 | 前端实际 | 说明 |
|---|---|---|
| career（就业规划） | employment（就业指导） | 文档描述的 Agent type 与前端 `growth.js` 中使用的 type 不一致；后端用 `career`，前端映射为 `employment` |

### 4.2 页面结构

| 产品文档 | 前端实际 | 差距 |
|---|---|---|
| Tab Bar 第三项为"成长" | 正确 | 但 doc 没有描述 Tab "成长" 页面的内容（四个方向卡片 + 沙盘入口） |
| "今日"是 Tab 第二项 | 实际 `app.json` 配置是 **schedule 页**作为 Tab | 文档将 index 首页概览和 schedule 日程页混在一起描述为"今日模式" |

### 4.3 沙盘流程

| 文档描述 | 前端实际体验 |
|---|---|
| "成长"Tab 点击 → 四个方向卡片 → 选方向 → Agent 对话 | **额外一步**："不知道选什么？" → 启动沙盘 → 沙盘对话 → 结果页（含匹配度/方向推荐）→ 选方向 → Agent 对话 |
| 未描述沙盘结果页的交互路径 | 前端有完整的 `sandbox-result` 页面作为沙盘与 Agent 之间的桥梁 |

## 六、总结

### 关键问题（按优先级）

1. **品牌命名不统一**：iCampus vs CampusPal 需要二选一
2. **API 文档与前端脱节**：前端调用了文档未列出的端点（如 `/api/v1/today/overview`、报告 PDF 端点），文档列的端点前端未必全用
3. **Agent type 命名不一致**：文档 `career` vs 前端 `employment`，可能导致接口对接失败
4. **AI 助手模式选择页未入文档**：作为独立枢纽页，应在产品文档中拥有独立章节
5. **个人中心功能网格**：4 个功能入口中 2 个未实现，文档也未提及
6. **沙盘结果页**：文档描述了沙盘的 4 个阶段但没描述结果展示页 UI，前端已设计了完整的交互（匹配度、洞察、方向推荐）
7. **报告页高级能力**：文档将 PDF 下载列入"规划中"，但前端按钮已就位
